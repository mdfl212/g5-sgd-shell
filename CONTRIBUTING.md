# Contributing

1. Keep changes small and explain the problem they solve.
2. Preserve the eight-step narrative spine and all subject palettes.
3. Do not invent clinical facts or references to make a slide look complete.
4. Use synthetic cases for public examples and tests. Never commit identifiable patient data.
5. Keep source figures undistorted and make arrows visible above flowchart nodes.
6. Update `SKILL.md`, `CHATGPT_INSTRUCTIONS.md`, and relevant docs when behavior changes.
7. Before proposing a release, run `python scripts/check_package.py` and, once implemented, the full build and visual QA workflow.

## Pull request checklist

- [ ] Scope and rationale are documented.
- [ ] Locked spine and branding remain intact.
- [ ] Source fidelity and citations are preserved.
- [ ] Tests or validation steps are included where applicable.
- [ ] Documentation accurately distinguishes implemented and planned features.
